# Schema

`data/index.json` is the manifest. `data/<id>.json` is one principle. Nothing else in this
repository is data, and nothing here knows about any application that consumes it.

## index.json

```json
{
  "version": 1,
  "generated": "scripts/build.py",
  "principles": [
    { "id": "customer-obsession", "name": "Customer Obsession", "sort": 1,
      "file": "data/customer-obsession.json" }
  ]
}
```

Generated by `scripts/build_index.py`, never hand edited. `scripts/validate.py` fails when it drifts from the record files.
It exists so a browser can discover the set without globbing a directory.

## data/&lt;id&gt;.json

```json
{
  "id": "customer-obsession",
  "name": "Customer Obsession",
  "sort": 1,
  "definition": "Leaders start with the customer and work backwards.",
  "terms": [
    { "id": "co", "label": "CO", "kind": "alias" },
    { "id": "customer-advocacy", "label": "customer advocacy", "kind": "equivalent" },
    { "id": "user-empathy", "label": "user empathy", "kind": "facet",
      "rows": ["product-design", "responding-to-a-complaint"] }
  ],
  "rows": [
    { "id": "product-design", "situation": "On product design",
      "under": "...", "justRight": "...", "over": "..." }
  ]
}
```

## Rules

- `id` is kebab-case and matches the filename without `.json`.
- `sort` is one through 14 in teaching order, Customer Obsession first and Deliver Results last.
  Every value appears once.
- `definition` is the short company-agnostic statement of the principle.

### terms

The vocabulary a person might use to name this principle. One list, three kinds.

- `alias` is how it is written at Amazon. Abbreviations and short forms, `bfa` and `high bar`.
- `equivalent` is how everyone else says it, and it means the whole principle. `move fast`,
  `do more with less`.
- `facet` also means how everyone else says it, but it names one slice of the principle rather
  than all of it. A facet must carry `rows`, listing the row ids it covers.

`id` is the slug of `label` and must be unique across every principle, not just within one,
because a consumer addresses a term by id alone with no principle in the URL. Two labels that
slug to the same id are the same term, so `think big` and `think-big` may not both appear.

The distinction between `equivalent` and `facet` is the point of the list. A consumer showing
results for an equivalent shows everything it has for the principle. A consumer showing results
for a facet shows only what maps to those rows, so someone who asked for `user empathy` is not
handed the whole of Customer Obsession back.

### rows

The calibration taxonomy, and the anchor a facet points at.

- Five to 12 real situations per principle. Give each a kebab `id` and a short `situation` label.
- `under`, `justRight`, and `over` are one to three sentences each. Under is not trying. Over is
  the principle eating the job. Just right is the bar.
- Row ids are unique within a principle. A facet may only reference a row on its own principle.

### Style

Every string: no em dash, no `---`, Oxford commas, numbers under 10 spelled out.

## Consuming this repository

It is a Go module, so a Hugo site can mount it:

```
module github.com/kindel/principles
```

An application that serves JSON to a browser from its own origin should vendor a pinned copy
into its own tree with a script, and check that the copy still matches the pinned tag. A copy is
acceptable when it is generated and verified. A copy kept in step by a human reading this file
is not, which is the mistake this repository exists to correct.

Version with tags. A schema change is a major version, so consumers can move at their own pace.
